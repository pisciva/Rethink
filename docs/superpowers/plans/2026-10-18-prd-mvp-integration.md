Scope: the 39 approved FRs in `Rethink/docs/prd/requirements.md`, implemented through the active SwiftUI → API v2 → Supabase path. The source OI/OPS register remains authoritative; draft behavior must not be reported as approved educational assessment.

1. **C1 and configuration.** Make the Swift catalog honor per-capability support, align backend setup with the confirmed Supabase project `ogroqzktmwtsoiaasxnm`, and verify the API's public and authenticated boundaries.
2. **C3 diagnosis.** Keep Q1–Q3 and at most one Q4, preserve raw attempts and internal evidence, add bounded Q3 AI interpretation as an advisory input with deterministic system decision authority, and test invalid, contradictory, all-correct, and provider-failure cases. OI-01 remains open for final policy approval; OI-03 remains a held state.
3. **C4 guided learning.** Render the curated visual model as actual repeated groups in Swift, retain the worked steps and active partial practice, and expose draft practice feedback and completion without claiming understanding.
4. **C5 and C2/FR-X.** Verify eligibility, retry/transfer gating, valid-answer handling, scoped result messages, reinforcement, and map projection from the same journey. Optional Review remains ineligible for C5 under the user's temporary OI-02 direction.
5. **Integration and traceability.** Run backend tests/typecheck/build and Swift package/Xcode build as available. Map each FR to code and verification. Record live migration/deployment and human math/UX review separately from local test results.

## Completion boundary

Code coverage of a behavior does not close OI-01..03 or OPS-01..05. Final acceptance requires approved mathematical items/rubrics, reviewed decision rules, live API/database verification, iOS end-to-end testing, and separate usability testing (SC4).
